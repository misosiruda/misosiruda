## Current Trend Research

Checked on 2026-06-04:

- GitHub Docs: profile README is a customizable top-of-profile section. Public README content is visible to others.
  - https://docs.github.com/en/account-and-profile/concepts/personal-profile
  - https://docs.github.com/en/account-and-profile/how-tos/profile-customization/managing-your-profile-readme
- 2026 profile README guidance generally favors:
  - A short first-screen identity statement.
  - A "currently working on" section.
  - 3-5 strong featured projects instead of a long repository dump.
  - Meaningful stats or language cards.
  - Scannable whitespace and short sections.
- Commonly discouraged:
  - Visitor counters.
  - Huge badge walls.
  - Flashy animated typing text with little substance.
  - Exhaustive lists of every technology ever touched.
- Optional but popular:
  - GitHub Readme Stats cards.
  - Contribution snake animation generated by `Platane/snk`.

## Recommended Direction

Use a clean portfolio-style README:

1. Strong headline:
   - "Backend-first full-stack developer"
   - "AI automation and operations-focused systems"
2. Short Korean/English mixed copy:
   - Korean reads naturally to local visitors.
   - English headline improves quick international scanning.
3. Evidence-based project sections:
   - Recent active work.
   - Earlier foundation projects.
   - Public links only where repositories are public.
4. Compact tech stack:
   - Grouped by practical strength, not every package.
5. Light dynamic visuals:
   - Stats card and top language card.
   - Optional snake workflow only if it does not add maintenance noise.

## Public Safety Rules

- Do not expose private repo names from other organizations unless already public or intentionally visible.

- Avoid client-sensitive details, credentials, endpoints, or internal business logic.
